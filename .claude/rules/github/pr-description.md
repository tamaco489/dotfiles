# PR のルール

## タイトルのフォーマット

```text
[変更種別] 変更内容の要約
```

例:

```text
[feat] Ghostty の背景透過設定を追加
[chore] zsh エイリアスを整理
```

| 要素     | 説明                                                        |
| -------- | ----------------------------------------------------------- |
| 変更種別 | `commit-types.md` の type と同じ (`feat`, `fix`, `chore` など) |
| 変更内容 | コミット群から自動生成。50文字以内を目安にする              |

## 本文の基本方針

- **git diff を見ればわかることは書かない** — 変更ファイル・行数・コードの内容は省略する
- **なぜ・何を変えたかを端的に書く** — 変更の背景と意図を伝える

## 書くこと

- 変更の背景・動機 (なぜこの変更が必要か)
- レビュアーが注意すべき点・影響範囲
- 既知の制約・今後の課題があれば簡潔に

## 書かないこと

- 変更ファイルの列挙 (git diff・コミット一覧で確認できる)
- 自明な変更理由 (「設定を変えたので更新した」など)
